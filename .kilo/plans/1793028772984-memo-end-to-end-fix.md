# Memo End-To-End Fix

Status: Finalized for implementation review. Only this plan file changed; no source changes, builds, tests, or deployments have run in this session.

## Goal And Scope

For an already scanned receipt with an active imported incoming-key handle, an explicit memo request must fetch the correct full transaction, decrypt the selected action locally, preserve the memo's actual format, save it encrypted, and display it. Offline transaction import must use the same verification/decryption path with zero relay requests. A saved memo must remain viewable after reopening and unlocking the workspace without another transaction fetch.

- Preserve the current dashboard and browser-worker architecture, incoming-only key policy, exact decimal-string zatoshis, and testnet/regtest boundaries.
- The user selected hosted rollout, including Render if relay changes are required.
- The user selected a narrow pinned dependency-feature patch instead of local C compiler installation.
- Git commits, push, PR creation, and merge were not authorized; the publishing question was dismissed. Do not infer permission from "continue" or hosted deployment approval.
- Key persistence/automatic handle restoration, general disclosure-export repair, unrelated dashboard changes, mainnet, and user-secret access are out of scope. A new decryption still requires the context's active handle; missing handles must fail explicitly. Cached memo viewing must not require one. Do not broaden the existing simulated disclosure-export format or treat it as verified encryption.
- Testnet is the primary memo flow. An unconfigured regtest upgrade schedule must fail explicitly; inventing a new regtest consensus profile is out of scope.

## Confirmed Causes

1. `crates/vinca-wasm/src/lib.rs` contains a memo-decryption export, but the generated package under `apps/web/src/wasm/` does not expose it. `inspection.worker.ts:211-217` therefore returns `INSPECTION_UNAVAILABLE`. A frontend build alone does not regenerate WASM.
2. `services/chain-relay/src/upstream/lightwalletd.rs:272-281` sends display-order txid bytes to lightwalletd, which expects protocol-order bytes. Compact scanning already converts hashes to display order; reverse only at the relay/gRPC boundary.
3. `OfflineMemoImportDialog` is disabled. `LiveScanner.fetchAndDecryptMemo` drops `rawBytesHex`, and the viewer only accepts strings, losing binary-memo and no-memo distinctions.
4. Adding `zcash_primitives` pulls `zcash_transparent -> zcash_script/descriptor -> secp256k1-sys`, which compiles C even with top-level default features disabled. The descriptor feature is unused by Vinca's incoming-only parser.

## Implementation Order

1. **Unblock the existing Rust parser without installing compilers.** Vendor the exact locked `zcash_transparent 0.11.0` source under `vendor/zcash_transparent`, preserving provenance and licenses. Remove its unconditional `zcash_script` `descriptor` feature and enable `zcash_script/descriptor` only through `transparent-inputs`, whose descriptor-dependent module is already gated. Register `[patch.crates-io]` in the root `Cargo.toml` and update `Cargo.lock` offline without unrelated upgrades. Do not edit the global Cargo cache or replace transaction parsing/cryptography. Confirm the core/WASM graph no longer requires `secp256k1-sys`; stop and report any remaining mandatory native dependency rather than broadening the patch silently.

2. **Complete and verify the Rust memo boundary.** Review `crates/vinca-core/src/notes.rs`, domain/error types, and `crates/vinca-wasm` state/export. Accept exactly one raw serialized transaction, 1 byte through 2 MiB, with bounded decoded counts and no trailing bytes. Use upstream parsing and Orchard-family decryption, preserving canonical display txids. Enforce txid equality, transaction version/embedded branch against height/profile, retained pool, checked zero-based action index, authenticated incoming decryption, and exact amount equality. Require canonical decimal zatoshis within `0..=2100000000000000`. Bind handles to decoded networks in Rust as well as JS. Raw bytes cannot independently prove chain provenance. Do not use a guessed testnet branch for regtest.

3. **Keep ZIP-302 data lossless through the ABI.** Retain the existing result fields: `format`, `text`, and `rawBytesHex`. Extend `format` to `text | no-memo | arbitrary-bytes | future-format | legacy-nontext`. New worker results always carry the complete 512-byte memo as 1024 lowercase hex characters; `text` is the decoded text for text memos and empty for nontext formats. Use upstream ZIP-302 decoding: invalid UTF-8 is an error, `F6` plus zeros is no-memo, `FF` is arbitrary data, `F5` is legacy nontext, and other reserved encodings stay uninterpreted. All successfully inspected results use receipt `state: available`, with honest format-specific labels; failures must not become success. Persist the same fields, making raw metadata optional only for already stored legacy records. Never infer missing bytes or convert old empty text into a no-memo assertion. Update Rust serialization, TS contracts, scanner mapping, and dialog callback return types together.

4. **Prove and bundle the WASM path before enabling the UI.** Regenerate `apps/web/src/wasm/vinca_wasm.js`, `vinca_wasm.d.ts`, `vinca_wasm_bg.wasm`, and `vinca_wasm_bg.wasm.d.ts` together. Check that the Rust target and cached wasm-bindgen executable already exist and match locked version `0.2.129`; wasm-pack can install a missing target even in no-install mode. Use locked/offline Cargo and installed tools only, with no-install/no-opt modes or direct Cargo plus matching cached bindgen. Invoke the real generated memo export with a successful fixture. Use its typed export in the worker after regeneration, removing the stale-package reflection workaround. Never hand-edit bindings or pair a new UI with an old binary.

5. **Fix the relay and bounded fetch contract.** In `services/chain-relay/src/upstream/lightwalletd.rs`, reverse the decoded 32-byte display txid exactly once into `TxFilter.hash`; keep display-order URL/cache keys and returned raw bytes unchanged. Correct `TxFilter.index` to protobuf `uint64` zero. Reject empty/oversized results, align Tonic decoding bounds with the operator response ceiling, and do not cache failures. Remove URI/query/txid fields from routine DEBUG tracing. In `apps/web/src/adapters/relay-client.ts`, cap transaction bodies at the core's 2 MiB limit before unbounded buffering and keep the timeout active through body reading. Surface bounded structured relay errors for retry. Never send private key/receipt/memo fields; do not change the public `/tx/{network}/{displayTxid}` API.

6. **Connect fetch/offline bytes, persistence, and workspace state.** In `LiveScanner`, reuse one verified transaction-bytes-to-memo operation for relay and offline input. Preserve the receipt's identity, amount, source, and evidence; await the existing encrypted receipt write before saved success. Add `importOfflineMemo(receiptId, txBytes)` beside `requestMemo`, returning typed memo data instead of a string. Require an unlocked live workspace and the context's active handle; return cached available memos without fetching. Guard decryption, persistence, and presentation with the current workspace/request generation. Lock/reset/deletion must invalidate work; navigation/target changes must not reopen the old viewer. Persistence failures leave the receipt unchanged and retryable.

7. **Complete the existing dialogs and viewer.** Wire `memo-dialog.tsx` and `routes/app/context-detail.tsx` to typed results. Replace the offline placeholder with bounded raw hex input: validate even length, syntax, and decoded size before allocation; allow at most 2 MiB decoded bytes. Reject JSON/RPC envelopes and compact/protobuf data. Preserve explicit relay consent, pending/error/retry, and no automatic fetches. Render text as untrusted React text with preserved whitespace and bounded wrapping/scrolling. Distinguish no-memo, empty text, arbitrary bytes, and future/legacy nontext; show raw hex without HTML interpretation. Use existing Radix dialogs for keyboard/focus behavior. Clear private memo UI on lock and target changes. Offline import must never invoke the relay.

8. **Record actual status and perform the gated rollout.** After authorized validation, update `implementation docs/projectcontext.md`, the PRD Phase 5/8 checkboxes and evidence rows, and memo-related README/UI limitations. Record source completion separately from commands/results and live receipt evidence. Deploy the corrected Render relay and matching Vercel frontend only after the relevant gates pass. If the existing rollout requires a Git publish or unavailable credentials/build tools, report that gate and stop; do not commit, push, merge, install tools, read secret files, or deploy stale source to bypass it.

## Rollout And Completion Criteria

- Render `/ready` and compact-block success are not proof that `/tx` works. Verify the corrected transaction route independently.
- Vercel must serve the newly built, matching worker/JS/WASM artifacts, including on a fresh session and after reloading an older session.
- Use public synthetic fixtures for automated/browser decryption checks and a known non-user public testnet transaction for an authorized hosted `/tx` smoke test. Do not query the user's transaction or access their incoming key/passphrase without separate explicit authorization; never request keys in chat.
- A user's memo is not "verified" merely because fixtures pass. Report protocol-vector, browser-flow, hosted-asset, and authentic live-receipt evidence separately.
- Completion requires successful explicit fetch and offline decryption, honest format display, encrypted cached reopening, and visible/retryable failures. Hosted completion additionally requires validated relay/frontend deployment and an authorized public testnet smoke case.
- Open external gates, not assumed approvals: compiler-equipped relay validation, an available authorized source/artifact publication route, deployment credentials through normal tooling, and consent for any authentic transaction-interest query. Git publication and private-key access remain outside this plan's authorization.
